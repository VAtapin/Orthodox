# Расписание

Правила — CPT `prihod_service`, meta `_prihod_service`. `kind` regular/single/holiday,
date/until, weekdays (ISO 1–7), time/end, location_id, timezone. Пустой timezone
наследуется от места, затем от прихода. Публично выводятся только опубликованные
службы в опубликованных местах. Календарь фактические службы не генерирует.

Исключения — словарь original_date → cancel/replace. При replace сохраняются
новая дата, время, окончание, место и разрешённый timezone. ID occurrence:
`service_id:original_date`. Перенос из-за границы периода учитывается по новой дате.
Отмена показывается в расписании, но исключается из поиска ближайших служб.

`Occurrences` — чистый движок календарной арифметики. Диапазон полуоткрытый и
ограничен 370 днями. Дни перебираются в местном timezone, не шагами по 86400 секунд.
Несуществующее весной время пропускается, при осеннем fold выбирается ранний UTC.
Разовая служба и перенос на несуществующее время отклоняются при сохранении.
Окончание <= начала относится к следующему местному дню.

Админка использует capability manage_prihod_schedule и nonce; ошибки сохраняют
предыдущее правило целиком. Данные не удаляются при отключении модуля.
Динамические блоки/шорткоды вычисляют актуальное расписание при выводе.
CSS печати скрывает элементы управления, JS кнопки вызывает стандартную печать браузера.

RC.2: три отдельных публичных представления — неделя с группировкой по дням,
календарный месяц с сеткой понедельник–воскресенье и список. Переключатель вида и
предыдущий/следующий период/сегодня сохраняют маршрут страницы и фильтр места.
Месячные ячейки учитывают timezone прихода; дни недели и месяцы локализованы Core.
