# Georg-Kloster Connect Hub 0.2.0

Универсальный плагин коммуникаций для WordPress 6.5+/PHP 8.0+.
Пакет разрабатывается и проверяется в одноразовом WordPress; наличие кода
интеграции не означает подтверждённую доставку через реальный аккаунт.

Меню: **Коммуникации / Kommunikation / Connect Hub**.
Разделы: Формы, Сообщения, Публикации, Telegram, WhatsApp, Соцсети, Настройки.
Русский и немецкий интерфейс поставляются в собственных PO/MO и JSON.

## Формы и сообщения

Каждая форма имеет собственное название, темы, заголовок, описание, кнопку,
адрес уведомлений и переключатель приёма. Темы и содержание произвольные:
церковные вопросы, поставки угля/молока или любые другие обращения.
Размещение: `[gkch_form id="123"]` либо блок «Форма» с выбором формы.
Старые `[gkps_contact_form]` и `gkps/contact-form` используют прежнюю форму
по умолчанию. Её настройки не копируются поверх новых форм.

Входящие сообщения хранят идентификатор и название формы; доступны фильтры
по форме и статусу. Закрытые сообщения доступны сотрудникам и после отключения
публичного приёма. Ответы по email, внутренние заметки, назначение сотрудника,
журнал почтовых попыток и WordPress privacy exporter/eraser сохранены.
Одноразовый токен привязан к форме; проверяются nonce, согласие и rate limit.
Полный page cache нужно исключить для страниц с формами.

## Публикации и подключения

В «Публикациях» выбираются опубликованная запись WordPress и конкретные каналы.
Этот же выбор доступен в редакторе записи. Сетевые отправки выполняет WP-Cron,
история показывает очередь, обработку, успех, ошибку и отмену. Для повторной
отправки проверяются права на исходную запись, состояние подключения и получатель.
В соцсети не передаются закрытые сообщения из форм.

| Канал | Реализованный поток | Требования |
| --- | --- | --- |
| Telegram | Публикации, уведомления; отдельный opt-in полных сообщений и ответов в личном чате | Bot token, Chat ID, права бота; для ответов — выбранный сотрудник и проверенный webhook |
| WhatsApp | Исходящие шаблонные сообщения | Cloud API, согласие получателя, одобренный шаблон; входящие ответы не импортируются |
| Facebook | Текст и ссылка на странице | Page token с правами публикации, Page ID, версия Graph API |
| Instagram | Миниатюра JPEG и подпись; создание контейнера → фоновая проверка → публикация | Профессиональный аккаунт, связанная Facebook Page, нужные разрешения, общедоступный HTTPS JPEG |
| VK | Текст и ссылка на стене | Пользовательский токен с правом wall, идентификатор пользователя/сообщества, версия API |
| OK | Текст и ссылка в группе | Токен, публичный/секретный ключи приложения, GROUP_CONTENT и идентификатор группы |

Instagram использует один сохранённый контейнер при повторах. VK получает
стабильный GUID публикации. Если после отправки OK соединение оборвалось,
результат считается неопределённым: автоматического повтора нет, сотрудник
сначала проверяет аккаунт и явно подтверждает отсутствие публикации.
Видео, reels и карусели в этот выпуск не входят.

Токены вводятся только в WordPress, сохраняются без autoload и не выводятся
назад в полях. Успешное сохранение настроек означает только корректность
обязательных полей; разрешения приложения и реальную доставку проверяет
владелец со своими аккаунтами. Секреты не следует отправлять в чат или Git.

## Смена пакета и установка

Сборка: `python scripts/package.py --only connect-hub`.
Результат: `build/georg-kloster-connect-hub-0.2.0.zip`.
Загрузить ZIP как **новый плагин**, затем активировать. При активации прежний
`georg-kloster-prihod-social` отключается; его параметры сохраняются. Для
сетевого прежнего плагина нужна активация нового для всей сети.
Внутренние `gkps` options, post types, права, cron hooks и Telegram REST paths
сохраняются. Деструктивных миграций нет. Внешние каналы не включаются автоматически.
Установка на сайт выполняется владельцем через ZIP; SSH/Composer/Node build
для установки не нужны.

## Проверки и источники протоколов

`tests/connect-hub-blueprint.json` предназначен только для одноразовой базы:
проверяет переход с предыдущего development ZIP, несколько независимых форм,
права, привязку токена к форме, маршрутизацию уведомлений, три языка меню,
очередь, контракты запросов, ошибки API и повторы. HTTP и email перехвачены
только в тесте; это не проверка настоящих аккаунтов.

Официальные контракты: [Meta Instagram API collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api),
[VK API schema](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json),
[OK mediatopic.post](https://apiok.ru/dev/methods/rest/mediatopic/mediatopic.post),
[подпись запросов OK](https://apiok.ru/dev/methods/).
