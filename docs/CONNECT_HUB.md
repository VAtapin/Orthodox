# Georg-Kloster Connect Hub 0.3.2

Универсальный плагин коммуникаций для WordPress 6.5+/PHP 8.0+.
Пакет разрабатывается и проверяется в одноразовом WordPress; наличие кода
интеграции не означает подтверждённую доставку через реальный аккаунт.

Меню: **Коммуникации / Kommunikation / Connect Hub**.
Разделы: Формы, Сообщения, Публикации, Настройки.
В «Настройках» вкладки: Общие, Telegram, WhatsApp, Facebook, Instagram, VK и OK.
Отдельных пунктов каналов и «Соцсети» нет. Сохранённые подключения, обработчики,
параметры приёма/ответов Telegram и шаблоны WhatsApp сохранены. Старые адреса
страниц Telegram/WhatsApp перенаправляют в соответствующие вкладки; сохранение
подключений и настройка приёма ответов возвращают туда же.
Русский и немецкий интерфейс поставляются в собственных PO/MO и JSON.

## Формы и сообщения

Каждая форма имеет собственное название, темы, заголовок, описание, кнопку,
адрес уведомлений и переключатель приёма. Темы и содержание произвольные:
церковные вопросы, поставки угля/молока или любые другие обращения.
Размещение: `[gkch_form id="123"]` либо блок «Форма» с выбором формы.
Старые `[gkps_contact_form]` и `gkps/contact-form` используют прежнюю форму
по умолчанию. Её настройки не копируются поверх новых форм.

Входящие сообщения хранят идентификатор и название формы; доступны фильтры
по форме и статусу. Закрытые сообщения доступны сотрудникам и после отключения
публичного приёма. Ответы по email, внутренние заметки, назначение сотрудника,
журнал почтовых попыток и WordPress privacy exporter/eraser сохранены.
Одноразовый токен привязан к форме; проверяются nonce, согласие и rate limit.
Полный page cache нужно исключить для страниц с формами.

## Публикации и подключения

В «Публикациях» настраиваются правила автоматической отправки (до 100 правил):

- **Новые записи WordPress**: заголовок, анонс и ссылка при первой публикации,
  во все выбранные каналы или с фильтром по рубрике. Отложенные записи WordPress
  также поддерживаются. Сохранение правила не отправляет существующие записи;
  исправление и повторная публикация уже отслеженной записи не дублируют отправку.
- **Запланированные сообщения и напоминания**: собственный текст до 900 символов,
  необязательная ссылка, разовая будущая дата либо ежедневное/еженедельное
  расписание с выбором дня и времени. Для Instagram выбирается общедоступный
  JPEG из медиатеки; у новых записей используется их миниатюра JPEG.

У каждого правила есть название, переключатель отправки и собственный набор
каналов. Новые правила выключены по умолчанию; включить правило можно после
настройки выбранных каналов. Редактор правил требует прав настройки коммуникаций
и публикации записей. При выполнении проверяются сохранённый владелец правила,
актуальная версия правила, подключение, получатель и доступность исходной записи.
Изменение/отключение/удаление правила блокирует его ожидающие отправки; уже
опубликованные материалы на внешних площадках не удаляются. История сохраняется.

Расписание следует часовому поясу WordPress и переходам летнего/зимнего времени.
В несуществующий весенний час PHP переносит время вперёд (02:30 → 03:30).
WP-Cron запускается при посещении сайта или серверным планировщиком; точность
до минуты зависит от его запуска. Опоздавшее правило выполняется один раз,
пропущенные интервалы не рассылаются пачкой. Смена часового пояса пересчитывает
следующую отправку. Деактивация очищает события правил; активация восстанавливает
их из сохранённых настроек. Удаление правила использует штатную корзину WordPress.

Сетевые отправки выполняются только фоновой очередью. История показывает очередь,
обработку, успех, ошибку, отмену и позволяет повторить/отменить доступную задачу.
Ошибка постановки в очередь показывается у правила: такой канал не отправляет
пропущенный материал автоматически после исправления подключения. В соцсети
не передаются закрытые сообщения из форм. Старые задания из 0.2.0 сохранены;
интерфейс выбора одной записи и флажки отправки в редакторе заменены правилами.

| Канал | Реализованный поток | Требования |
| --- | --- | --- |
| Telegram | Публикации, уведомления; отдельный opt-in полных сообщений и ответов в личном чате | Bot token, Chat ID, права бота; для ответов — выбранный сотрудник и проверенный webhook |
| WhatsApp | Исходящие шаблонные сообщения | Cloud API, согласие получателя, одобренный шаблон; входящие ответы не импортируются |
| Facebook | Текст и ссылка на странице | Page token с правами публикации, Page ID, версия Graph API |
| Instagram | Миниатюра JPEG и подпись; создание контейнера → фоновая проверка → публикация | Профессиональный аккаунт, связанная Facebook Page, нужные разрешения, общедоступный HTTPS JPEG |
| VK | Текст и ссылка на стене | Пользовательский токен с правом wall, идентификатор пользователя/сообщества, версия API |
| OK | Текст и ссылка в группе | Токен, публичный/секретный ключи приложения, GROUP_CONTENT и идентификатор группы |

Instagram использует один сохранённый контейнер при повторах. VK получает
стабильный GUID публикации. Если после отправки OK соединение оборвалось,
результат считается неопределённым: автоматического повтора нет, сотрудник
сначала проверяет аккаунт и явно подтверждает отсутствие публикации.
Видео, reels и карусели в этот выпуск не входят.

Токены вводятся только в WordPress, сохраняются без autoload и не выводятся
назад в полях. Успешное сохранение настроек означает только корректность
обязательных полей; разрешения приложения и реальную доставку проверяет
владелец со своими аккаунтами. Секреты не следует отправлять в чат или Git.

## Смена пакета и установка

Сборка: `python scripts/package.py --only connect-hub`.
Результат: `build/georg-kloster-connect-hub-0.3.2.zip`.
Для установленного Connect Hub 0.2.0/0.3.0 загрузить ZIP и подтвердить замену версии.
При первой установке загрузить ZIP как **новый плагин**, затем активировать. При активации прежний
`georg-kloster-prihod-social` отключается; его параметры сохраняются. Для
сетевого прежнего плагина нужна активация нового для всей сети.
Внутренние `gkps` options, post types, права, cron hooks и Telegram REST paths
сохраняются. Деструктивных миграций нет. Внешние каналы не включаются автоматически.
Установка на сайт выполняется владельцем через ZIP; SSH/Composer/Node build
для установки не нужны.

## Проверки и источники протоколов

`tests/connect-hub-blueprint.json` предназначен только для одноразовой базы:
проверяет переход с предыдущего development ZIP, несколько независимых форм,
права, привязку токена к форме, маршрутизацию уведомлений, три языка меню,
очередь, контракты запросов, ошибки API и повторы. Автоматизация проверяет
первую публикацию, рубрики, отложенные записи, повторы, разовые напоминания,
DST, отмену устаревших заданий и права владельца. HTTP и email перехвачены
только в тесте; это не проверка настоящих аккаунтов.

Официальные контракты: [Meta Instagram API collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api),
[VK API schema](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json),
[OK mediatopic.post](https://apiok.ru/dev/methods/rest/mediatopic/mediatopic.post),
[подпись запросов OK](https://apiok.ru/dev/methods/),
[WordPress single-event Cron](https://developer.wordpress.org/reference/functions/wp_schedule_single_event/),
[событие после сохранения записи и метаданных](https://developer.wordpress.org/reference/functions/wp_after_insert_post/).

## Справка по шорткодам и язык

«Шорткоды и блоки» доступны под формой редактирования в разделе «Формы» и
в «Настройки → Общие». Такое же описание поставляется в readme.txt пакета.

- `[gkch_form id="123"]` выводит форму с указанным ID из таблицы форм.
- `[gkps_contact_form id="123"]` — совместимое прежнее имя с теми же параметрами.
- Без `id` или с `id="0"` используется форма по умолчанию.
- `title`, `intro` и `submit` меняют только отображаемые заголовок, вступление
  и подпись кнопки. Например: `[gkch_form id="123" title="Напишите нам" submit="Отправить"]`.
  Темы, получатели и сохранённые настройки формы не меняются.

Форма и общий приём сообщений должны быть включены. Вместо шорткода можно
добавить блок «Форма» и выбрать форму. PHP/JS/CSS пакета содержат английские
UI-строки; RU/DE PO/MO/JSON сохраняют локализованный интерфейс. Пользовательские
сообщения, темы и настройки при смене языка не переписываются.
