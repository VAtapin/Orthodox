# Обращения

Private CPT prihod_request + private prihod_message, без публичного REST, комментариев
и стандартной админки CPT. Сотрудники работают в «Приход → Обращения» только с
view_prihod_requests; ответ, назначение и удаление дополнительно требуют отдельных прав.
Редактор WordPress не имеет доступа. Отправитель не обязан иметь WordPress user ID.

Форма: nonce, одноразовый token (1 час), honeypot, consent и 5 отправок на 15 минут
по HMAC от IP. Сырой IP не сохраняется. Подтверждение не раскрывает номер/содержание
обращения. Страницу формы следует исключить из полного page cache.

Сообщения имеют направление internal или email; внутренние заметки не отправляются.
Email отправляется сразу через wp_mail/PHP; WP-Cron используется только для
повтора после ошибки (всего максимум3попытки) и retention. pending/sent/failed
видны сотруднику. `sent` — принятие транспортом, не доставка в ящик; сохраняются
время попытки, результат и безопасный код ошибки без содержания письма.

Core rc.16: можно продолжать отвечать на сообщение бота после статуса «Отвечено»;
каждый новый Telegram update создаёт отдельный private prihod_message и отдельное
письмо, повтор update не дублирует запись/отправку. Поддержаны фотографии PNG/JPEG
и статические WebP-стикеры (конвертация в PNG через GD), максимум4MiB/4млн пикселей.
Подпись сохраняется как текст; изображение в HTML-письме — MIME Content-ID,
есть текстовая версия. Видео/анимации/документы не пересылаются: сотрудник получает
объяснение, оно сохраняется внутренней заметкой. Временный сбой загрузки допускает
повтор webhook до сохранения ответа. Изображения хранятся base64 в закрытой meta
сообщения, а не в uploads/медиатеке; просмотр требует view_prihod_requests + nonce.
Экспорт/удаление персональных данных учитывают изображения вместе с историей.

Входящие ответы посетителя по email автоматически не принимаются. Для настоящего
канала нужен выделенный ящик домена монастыря и подключение IMAP внутри Прихода
(не Gmail): проверка владельцем доступа, сопоставление Message-ID/In-Reply-To и
проверка отправителя, дедупликация входящих писем. Этот канал сейчас не реализован
и не подключён; пароли вводятся только в будущей форме WordPress, не в чат.
Подробности реализации/диагностики: TELEGRAM_DIALOG.md.

Удаление — отдельная capability и подтверждение. Удаляются сообщение, история и
запланированные отправки. Privacy callbacks интегрированы в стандартный WordPress
процесс с подтверждением владельца email. Retention удаляет только закрытые обращения
старше настраиваемого срока по последнему изменению (по умолчанию 365 дней), пакетами
по 100 за ежедневный запуск. При отключённой форме privacy и фоновые задачи сохраняются.

Locks хранятся в options без autoload, имеют срок и compare-and-delete owner token.
Никакие credentials/содержимое обращений не записываются в Git или logs плагина.
