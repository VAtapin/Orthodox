# Оформление «Прихода»

`screenshots/` содержит все 15 исходных PNG из предоставленного владельцем
`docs/UI`. Копии совпадают побайтно; `manifest.json` связывает имена с оригиналами
и SHA-256. Каталог исходников не изменялся. Эти изображения — макеты, а не снимки
работающего продукта.

`verification/` — реальные снимки одноразового WordPress Playground с тестовыми
данными. Внешние HTTP и email заблокированы, формы не отправлялись. Ошибка
календаря в боковой колонке показывает реальное состояние при недоступном API.
Это не подтверждение живых оплат, доставки или данных календаря.

Сохранены пять схем, четыре языка интерфейса и мобильные виды. Подписи материалов
и меню — тестовый контент; язык интерфейса не переводит его автоматически.
Для фотографического совпадения с макетами владелец выбирает реальные изображения
храма и галереи в медиатеке. Без фото тема использует нейтральный фон.

Макеты не устанавливают фиксированные суммы, праздники, священнослужителей или
тексты. Школьные, паломнические и другие информационные страницы создаются обычными
блоками WordPress и назначенными шаблонами; отдельные бизнес-сервисы из рисунков
не создавались. Оплаты и их статусы принадлежат kloster-prayer, календарные сведения
— orthocal, службы и обращения — Core.

Файлы темы не перезаписывают сохранённые пользователем шаблоны/стили WordPress.
Основные компоненты и переключатель оформления описаны в prihod-theme/README.md.

Снимки форм donation-1.0.2-review.jpg и prayer-1.0.2-review.jpg подтверждают
переходы настоящего Orthodox Donations 1.0.2: три и пять шагов. Итоговые кнопки
отправки не нажимались. Снимки живого WordPress, дашборда и консоли —
../test-server/. Ошибки API в локальном Playground не относятся к текущему
WordPress на сервере: там блокировка снята и календарь работает.

16-theme-options-reference.png — предоставленный пример Avada. Он задаёт
ориентир панели с разделами, а не требование копировать полный набор её настроек.
Панель «Прихода» содержит семь разделов и собственные пять схем оформления.
