# «Приход» 0.2.0

Текущая линейка содержит два плагина: «Приход» (`georg-kloster-prihod-core`)
и «Коммуникации» (`georg-kloster-connect-hub`). Тема остаётся самостоятельной.
«Приход» объединяет профиль, духовенство, места служения, службы и календарь.
Демо-импорт RU/EN и его отдельные подтверждения сохранены.

## Места и изображения

В «Приход → Места служения» один список прежних мест Core и Schedule.
Новые места создаются как `gkpc_location`. Прежние `gkpsch_location` сохраняют
тип и ID; они скрыты как отдельный пункт меню, но редактируются в общей системе.
Записи с одинаковыми названиями не склеиваются автоматически: это могут быть
разные места. Удаление/перенумерация записей и замена ссылок служб не выполняются.

Общие поля места — описание, адрес, телефон, email, часовой пояс. Старый
`_gkpsch_details.timezone` читается как резервное значение; новые данные сохраняются
в `_gkpc_details`. Список мест в службе, публичные блоки и счётчики учитывают оба типа.
Прежние права доступа к местам Schedule сохраняются.

Отдельный блок редактора «Логотип и фотографии места служения» предлагает
выбрать логотип и до 24 фотографий из медиатеки. `_gkpc_media` хранит ID,
порядок и отдельный логотип; текст описания и файлы изображений не переписываются.
При отсутствии новых настроек прежняя миниатюра используется как фотография.
Явная очистка убирает только привязки. Поддержка миниатюр со стороны темы
не требуется. Запись проверяет nonce, права на место и загрузку файлов,
тип вложения и лимит; автосохранения и редакции не меняют привязки.

Логотип и фотографии отображаются в `gkpc/places` / `[gkpc_places]`, а также
над расписанием конкретного места. Если опубликовано только одно место,
его изображения показываются и без фильтра. Для общего расписания нескольких
мест произвольный логотип не выбирается. Черновики мест публично не выводятся.

## Расписание и календарь

Исходники модуля перенесены в `georg-kloster-prihod-core/schedule/`.
Прежнее пространство имён `GeorgKlosterPrihodSchedule`, `gkpsch_service`,
метаданные, cron hooks, REST namespace, блоки и шорткоды сохранены.
Новой копии бизнес-логики рядом со старой нет. `Directory` модуля — фасад
общего каталога мест. В меню «Приход» находятся службы и настройки расписания;
отдельного верхнего меню «Богослужения» нет.

Публичный календарный API использует фиксированный `https://bible-desktop.com`.
Поле адреса убрано, сохранённый другой origin игнорируется. Настройка профиля,
икон и напоминаний остаётся. Сбои API не удаляют и не блокируют сохранённые службы.

## Обновление и сборка

`python scripts/package.py --only parish-core connect-hub theme`
создаёт ZIP двух плагинов и темы. Прежний аргумент `parish-schedule` является
совместимым алиасом сборки «Прихода»; отдельный Schedule ZIP больше не создаётся.
Исторический `prihod/` не относится к текущей установке.

Обновить существующий Core через `build/georg-kloster-prihod-core-0.2.0.zip`
с подтверждением замены установленной версии. Slug и основной файл не меняются.
Прежний отдельный Schedule отключается тихо при активации нового «Прихода»
или первой загрузке после ZIP-обновления. Если его PHP-классы уже загружены,
они завершают этот запрос; следующий запрос использует встроенный модуль.
Для сетевого Schedule нужна сетевая активация «Прихода»; обычная активация
на одном сайте не отключает плагин всей сети. Старые файлы можно удалить
после проверки обновления; деактивация сама файлы и данные не удаляет.

Тема 0.4.35 обновляет раздел дополнений до двух карточек. Её обновление
нужно для нового списка дополнений; сам «Приход» работает и с другой темой.
Установка ZIP выполняется владельцем. SSH, Composer и Node build не нужны.

## Проверки

`tests/parish-merge-blueprint.json` проверяет объединение, сохранность данных,
меню, выбор обоих типов мест, изображения без поддержки миниатюр в теме,
сохранение/очистку/валидацию, nonce, права, фиксированный API и прежние блоки.
`tests/parish-upgrade-blueprint.json` использует настоящие старые ZIP Core 0.1.5
и Schedule 0.1.10; после копирования нового пакета проверяет переход через запрос
с уже загруженными старыми классами. Фикстуры запускаются только в одноразовом WP.
Отдельно сохраняются проверки демо, переводов и каталога дополнений темы.
Сетевые запросы в проверках перехвачены; это не проверка доступности живого API.
