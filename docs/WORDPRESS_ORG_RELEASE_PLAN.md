# Публикация темы и трёх плагинов в WordPress.org

Порядок выпуска: тема `georg-kloster-prihod`, затем независимые плагины
`georg-kloster-prihod-core`, `georg-kloster-prihod-social` и
`georg-kloster-prihod-schedule`. Каждый выпуск — отдельная законченная задача с
собственным проверенным ZIP. Отправка в каталог и установка на сайт выполняются
отдельно от сборки и Git push.

Состояние 16 октября 2026: тема 0.4.0 и её отдельный ZIP подготовлены. Пять
оформлений проверены на desktop/mobile; Theme Check, чистый WordPress 6.5/PHP 8.0
и совместимость с текущим Core прошли. Настройки фотографий разделов, карточек
и карты удалены из темы: изображения идут из страниц, а данные и формы будут
принадлежать плагинам. Содержимое главной страницы и блоки плагинов выводятся
без скрытой панели. Подача в каталог ещё не выполнялась. Пункты ниже описывают
исходные риски и критерии выпуска; работа
над тремя плагинами остаётся следующими отдельными этапами.

## 1. Тема `georg-kloster-prihod`

Тема отвечает за представление стандартных страниц и записей, навигацию,
фотографии, цветовые схемы и настройки внешнего вида. Она должна работать на
чистом WordPress без любого плагина проекта.

Перед подачей перенести из текущей темы функциональность плагинов: создание
демо-страниц и навигации, собственные блоки, SEO/OpenGraph и изменение поведения
форм записок и пожертвований. Демо-импорт принадлежит Core; формы и каналы —
Social. Вместо собственных блоков темы использовать блоки WordPress, шаблоны
и части шаблонов. Сохранить пять оформлений там, где они реализуемы средствами
темы, и проверить обычные страницы без Core.

Пакет: папка, `Theme Name` и `Text Domain` согласованы с slug; в `style.css`
есть обязательные заголовки; `readme.txt` описывает установку и ограничения.
Список ресурсов содержит авторство, лицензию и источник каждого изображения,
скрипта и шрифта. Скриншот отражает действительный вид темы и соответствует
формату каталога. ZIP не содержит тесты, временные файлы и плагины.

Проверки: PHP/JS/JSON, Theme Check, чистый WordPress с `WP_DEBUG=true`,
активация и просмотр desktop/mobile без Core, затем с установленными плагинами;
содержимое ZIP сверяется с проверенным исходником. Только после успешной
проверки пакет можно назвать готовым к подаче.

### Подтверждённые препятствия в текущем исходнике темы

- Шаблоны вызывают 13 собственных динамических блоков темы. Правила каталога
  тем запрещают custom blocks; замена должна сохранить согласованные виды
  страниц, а не подменить их пустыми или урезанными макетами.
- `includes/demo.php` создаёт страницы и навигацию. Демо-импорт прямо запрещён
  в настройках темы WordPress.org. Существующий Core уже имеет мастер страниц;
  эту функцию нужно завершить там.
- `includes/branding.php` выводит OpenGraph/Twitter metadata, а `assets/forms.js`
  меняет поведение форм пожертвований. SEO и поведение форм относятся к плагинам.
- У темы пока нет `readme.txt` и каталожного `screenshot.png`. Пять JPG-превью
  содержат фотографии и сведения демонстрационного монастыря; до включения
  в публичный ZIP нужны подтверждённые права на каждый ресурс или новые
  нейтральные снимки фактической темы.
- Простое переименование папки и text domain не делает текущую тему готовой
  к публикации; выпуск `0.4.0` возможен только после разделения кода и тестов.

## 2. Core `georg-kloster-prihod-core`

Профиль прихода, места служения, духовенство, их блоки/шорткоды и относящиеся
к ним права. Мастер первоначального создания страниц, если он сохраняется,
находится здесь и выполняет изменения только после явного действия владельца.
Core не требуется для активации темы и других двух плагинов.

Версия 0.1.0 реализует профиль, каталог и блоки/шорткоды без старого монолита.
Мастер пока не перенесён. Пакет проверен на чистом WordPress 6.5/PHP 8.0;
Plugin Check и редакторский интерфейс ещё предстоит проверить перед подачей.

## 3. Social `georg-kloster-prihod-social`

Настраиваемые формы, обращения, закрытая история, email, Telegram, WhatsApp
и публикации Facebook Page. Каждый канал включается отдельно. Входящие ответы
WhatsApp являются новой функцией и не считаются реализованными до получения
настоящего webhook и проверки подлинности. Передача данных в каждый внешний
сервис описывается отдельно в `readme.txt`, включая условия отправки и ссылки
на условия использования и политику конфиденциальности.

## 4. Schedule `georg-kloster-prihod-schedule`

Службы, повторы, исключения, переносы, виды расписания, подсказки праздников
и иконы. Использует существующий календарный API через проверяемый адаптер;
некорректные или неполные ответы не должны давать PHP notices. Без Core
использует часовой пояс WordPress и не создаёт фиктивных данных.

## Общие условия подачи плагинов

- Публичное имя начинается с Georg-Kloster; slug, папка, главный PHP-файл,
  text domain, readme и сборка согласованы. Право владельца на бренд и домены
  должно быть подтверждаемо.
- У каждого плагина собственный уникальный префикс не короче четырёх символов
  для PHP-имён, options, transients, хуков, маршрутов, блоков и JS-глобальных
  переменных. Английские строки служат оригиналом для переводов.
- Читаемые исходники любого собранного JS/CSS доступны в ZIP либо по публичной
  ссылке в readme вместе с инструкцией сборки. Лицензии всех ресурсов проверены.
- Публичные маршруты намеренно открыты только там, где это необходимо;
  закрытые данные защищены правами и проверкой подлинности запросов.
- Plugin Check, PHP/JS checks и чистый WordPress с `WP_DEBUG=true` проходят
  на точном ZIP-кандидате. Версии в заголовке, `Stable Tag` и Git/SVN tag
  совпадают. После публикации отдельно проверяются публичный ZIP, обновления
  и официальные языковые пакеты.
