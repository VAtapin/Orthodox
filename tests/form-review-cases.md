# Проверка итогов штатных форм

Среда: одноразовый WordPress Playground, tests/design-blueprint.json,
настоящий Orthodox Donations 1.0.2 и тема «Приход». Не запускать финальный submit.
Сценарии выполнены 12.10.2026 через браузер; результаты и снимки:
docs/design-reference/verification-2026-10-12/form-review-cases.json.

1. О здравии → Молебен → имя «Тест» → test@example.org → Карта / Stripe.
   Итог должен повторять эти выбранные поля, настоящую сумму 20 EUR,
   показывать «Молебен — за 10 имён» с разделителем и две группы данных.
2. «Изменить: Способ оплаты» → PayPal → продолжить. Итог должен обновиться,
   поминовение, требы, имена и контакты должны сохраниться.
3. «Изменить: Поминовение» → Об упокоении → Панихида → пройти до итога.
   Итог показывает Об упокоении и Панихиду, а не прежний Молебен; PayPal сохранён.
4. Вернуться к оплате → Карта / Stripe. Итог должен отражать новый выбор.
5. Вернуться к именам → «Тест» и «Пример» отдельными строками → итог.
   Оба имени присутствуют, сумма берётся из штатного output, поля не дублируются.
6. Обычное пожертвование 15 EUR → тестовые контакты → итог: сумма и Stripe
   отображаются в группе пожертвования, контакты находятся в отдельной группе.
7. Повторить первый сценарий в classic/hospitality/editorial/tradition/blue
   при1122px; проверить мобильный390px. Нет горизонтального переполнения,
   все действия изменения доступны, нет невидимых полей финального подтверждения.

Во всех случаях не нажимать «Подать записку и пожертвовать» / «Пожертвовать».
Тестовые данные не вводить в живой сайт. Успешный платёж, письмо и обработка
отправленной записки этим тестом не подтверждаются.
