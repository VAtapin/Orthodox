# Статус «Прихода»

Реализованы этапы 1–6: Core, расписание, закрытые обращения, безопасный мастер,
права/диагностика/очистка, необязательная блоковая тема и адаптеры интеграций.
Core 1.0.0-rc.1; тема и три независимых подключения 0.1.0. ZIP собираются
командой python scripts/package.py. Это release candidate для установки и проверки владельцем.

Расписание учитывает IANA/DST, исключения и переносы. Обращения имеют закрытую
историю, email-очередь, явный retry, retention и privacy export/erase. Мастер
создаёт черновики после подтверждения, отдельно публикует и сохраняет ручные изменения.
Данные и бизнес-логика находятся в Core; тема и подключения работают самостоятельно.
Telegram, WhatsApp Cloud API и Facebook Pages используют opt-in, фоновые задачи,
ограниченные повторы и безопасные локальные статусы. Секреты вводятся владельцем в WordPress.

Адаптеры календаря и «Записок» используют их реальные блоки/шорткоды;
существующие пожертвования не дублируются. Исходники соседних проектов только прочитаны.
«Записки» 1.2.15 требуют WordPress 7.1 / PHP 8.4, хотя Core поддерживает WP 6.5 / PHP 8.0.
WordPress и production владельца не изменялись: установка оставлена владельцу.

Проверки: PHP syntax, 57 unit assertions, JavaScript syntax; одноразовый
WordPress Playground/SQLite — 78 integration assertions на WP 7.1.3 / PHP 8.4.25
и WP 6.5.13 / PHP 8.0.30 и 8.4.25. Самостоятельная работа темы и трёх подключений подтверждена.
HTTP и email в тестах перехвачены: реальные сообщения и платежи не отправлялись.

Не проверены живые внешние аккаунты/доставка, MySQL/Plesk и визуальная браузерная QA.
После разрешения владельца прошла совместная проверка с настоящими календарём 1.3.78
и «Записками» 1.2.15: активация, регистрация, вывод страниц календаря/форм мастера
и статусы адаптеров в одноразовом WP 7.1.3 / PHP 8.4.25 / SQLite.
Расширенный сценарий прошёл 87 проверок. Внешние HTTP/email заблокированы,
формы не отправлялись. Далее — тестовый сайт владельца и проверка доставки
с его аккаунтами. Полное ТЗ сохранено.
