# Статус проекта «Приход»

## Реализовано

Этап 1 Core, версия 0.1.0: устанавливаемый WordPress-плагин в `prihod/`, профиль
прихода, несколько мест служения, духовенство со связями с несколькими местами,
capabilities, административный интерфейс и небольшой PHP-контракт расширений.
Сохранение защищено правами/nonce, входные данные проверяются, вывод экранируется.
Деактивация и обычное удаление сохраняют данные и выданные права.
Полное ТЗ и направление проекта сохранены без сокращения конечного объёма.

## Решения

- Этапы реализации — по разделу 20 SPECIFICATION.md. Сейчас закончен только Core.
- Профиль — option; места и духовенство — CPT со стабильными WordPress ID.
- Данные и функции принадлежат плагину, тема необязательна.
- Раздельные capabilities; редактор не получает доступ автоматически.
- Именованные timezone для будущего DST-aware расписания. Фиксированный offset
  WordPress не используется как пояс прихода; в этом случае начальное значение UTC.
- REST namespace `prihod/v1` зарезервирован, REST routes пока отсутствуют.
- Расширения регистрируются на `prihod_register_integrations`. Реальные адаптеры
  календаря/«Записок» добавляются только после изучения их фактического кода.
- Владелец прямо указал устанавливать плагин самостоятельно. Production и его
  WordPress не изменялись; серверная команда deployment для этой задачи не требуется.

## Известные ограничения

Расписание, обращения, блоки/шорткоды, мастер, тема и реальные интеграции пока
отсутствуют. Зарезервированные capabilities не означают готовность этих модулей.
Нет собственного интерфейса назначения прав и подтверждаемого полного удаления
данных. Revisions охватывают название/описание записей, но ещё не их метаполя.
Не выполнялись браузерная QA, MySQL/MariaDB/Plesk-проверка и проверка WordPress.org.
GitHub Actions настроены; их успешное выполнение не утверждается без результатов CI.

## Проверки

- Локальный PHP 8.4.25: синтаксис всех PHP-файлов и 37 unit assertions — прошли.
- WordPress Playground / SQLite: 17 assertions на каждом сочетании:
  WordPress 6.5.13 / PHP 8.0.30; WordPress 6.5.13 / PHP 8.4.25;
  WordPress 7.1.3 / PHP 8.4.25 — прошли.
- Проверены реальные активация, capabilities, сохранение профиля/записей/связей,
  отказ редактору, доступ сотруднику с capability и сохранность при uninstall.
- `composer check` локально недоступен из-за отключённого OpenSSL у PHP;
  те же документированные проверки выполнены напрямую через PHP, без зависимостей.
- `git diff --check`, `git diff --cached --check`, stat и содержательный diff
  проверены; ZIP содержит только плагин.
