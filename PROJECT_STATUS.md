# Project status: Georg-Kloster Prihod

## Current state

The repository contains the Georg-Kloster Prihod theme (1.1.1), Parish Core (0.2.12), and Connect Hub (0.4.10 submitted to WordPress.org; local source may include unreleased changes). The theme has five visual styles, native Customizer controls, standard WordPress widget and primary/footer menu locations, English gettext source strings, and Russian, German, Polish, and Ukrainian catalogs. Footer links are managed by assigning a standard menu to the Footer menu location. Author: Atapin Vladimir (`atapin`); site: https://georg-kloster.ru/; email: atapin@gmail.com.

The footer no longer generates a fixed list of site links. It renders the standard WordPress menu assigned to the Footer menu location; per-language menus can be assigned through the normal WordPress/WPML menu workflow. The theme package has not been installed on production.

The merged Parish Schedule reads vestment recommendations from Bible Desktop `day.vestment.color`; API `violet` maps to the existing `purple` palette key. Existing manual service colors and date overrides remain available. Vestment stripes use a silver frosted pattern; mobile upcoming-service cards and weekly/list event content have extra spacing after the stripe. Parish Core 0.2.12 keeps compact titles within their sidebar cards, shows all provider commemorations in full schedule service cards alongside typikon marks, and clears the overview heading from its calendar badge. Production has not been updated.

The theme has compact optional-plugin cards for Parish, Connect Hub, Calendar Workshop, Orthodox Donations, and Slavonic Translator. Language switching is delegated to WPML or Polylang. The shared homepage map uses a full-width iframe.

The active theme on the test site `new.georg-kloster.ru` was updated from the current Git package (version 1.0.0). News and category archives use responsive card grids. The homepage service strip has a place logo, date calendar, and time clock with separate columns for date, time, and service title; the time column is widened and its stylesheet uses a file modification cache key so updates reach visitors. Narrow screens stack the strip without clipping. The classic hero motto stays in the text column. The live page retained its existing theme settings.

The monastery icon category archive has a dedicated class and 16:9 featured-image cards. In Posts → Categories, each category can align card images to the center, top or bottom; center remains the default. Post editing includes an optional featured-image text-wrapping setting; wrapping is disabled by default and becomes a stacked image on narrow screens. Theme controls are translated into Russian, German, Polish, and Ukrainian. Changes are committed in the repository but have not been deployed to a site.

The native `/news/` Posts page and “News” category archive share the catalog’s category chips and search controls. Filter terms are limited to categories used by published posts, and selected search/category filters are applied to the correct main query. Translated page/category URLs are resolved through WPML or Polylang.

The newsletter widget area is present on the homepage and news/archive views. It uses MailPoet form 2 (“Новости монастыря”), linked to “Рассылка новостей”; the theme now constrains the form to a 600px maximum width and uses tighter spacing and shorter controls. The old stock demo form remains in MailPoet but is no longer displayed publicly. The confirmation email uses Russian text and the theme palette, and the confirmation page layout is compact with its sidebar hidden. Double opt-in and MailPoet’s built-in CAPTCHA are enabled. MailPoet sending is still inactive (“Other” method awaits activation); WP Mail SMTP has an SMTP transport configured, but delivery has not been tested. No campaign or test email has been sent.

Connect Hub 0.4.10 keeps form notifications separate from public Telegram broadcasts. Forms send private inquiries only to their configured Chat IDs; publications go individually to each active bot subscriber who pressed `/start`. Bot language choices follow active WPML languages. Daily and weekly calendar messages use Telegram HTML and include every available commemoration and service, vestment-color markers and complete content split across Telegram-sized messages. Schedule messages list each service place once and link its address to Google Maps. News posts use the subscriber's translated title and a short HTML excerpt, the post's featured image, and a localized button that opens the translated article without printing its URL. News-command replies use the same compact format. Each Telegram command or reply can include localized inline buttons that open another configured command/reply, a regular HTTP(S) link, or a Mini App inside Telegram using an HTTPS Web App button. Connect Hub now publishes both language-specific and fallback Telegram command lists and restores Telegram's native Menu → Commands button on connection and `/start`. The command editor versions its JavaScript by file modification time to avoid stale cached controls without changing the plugin version. All built-in command visibility can be toggled; hiding `/start` or `/stop` removes it from command suggestions, while direct invocation remains available for subscription management. Incoming commands, form notifications, email replies, Telegram publications and subscriber broadcasts run in the triggering request without automatic retries. Calendar digests and scheduled publication rules retain their configured timing and then send directly. Forms and bot commands use separate WordPress-style list and edit screens. Bot replies use the WordPress visual editor with Telegram-supported formatting and up to ten photos or MP4 videos per language. Built-in and custom commands can return text, schedules, pages or news. Failed deliveries remain visible for manual retry. Standard interface text has RU/DE PO/MO catalogs. Production has not been updated.

## Connect Hub delivery

Connect Hub 0.4.10 sends Telegram updates synchronously to each subscriber's private chat, records individual outcomes, and permits manual retries after failure. Incoming bot commands, form notifications, replies by Telegram/email, webhook registration, and publications do not use delayed workers or automatic retries. WP-Cron remains only for calendar timing (daily digest and scheduled publication rules) and record retention. Social publication history now keeps up to ten attempts per job, including HTTP status, endpoint, API version, destination ID, and whitelisted API error fields; credentials and request bodies are excluded. Retry controls are removed from channel settings; failed posts are retried from Publication History, and existing posts can be sent again from their editor. Old queued items and stale scheduled hook records have not been migrated or deleted; legacy worker hooks are no longer registered. Production has not been updated.

VK setup now guides administrators to create a community access key with `wall` and `photos` permissions and accept community IDs with or without `club` and a minus sign, normalizing them for the VK API; the VK API version is fixed internally at 5.199. Facebook Graph API version is likewise managed internally at v27.0. Their version fields are hidden and setup guides are open by default. Incomplete enabled settings are saved with sending turned off and an actionable notice on the settings page; blank password fields preserve existing tokens. The post editor already exposes a VK publication checkbox when that channel is complete and enabled. VK community ID normalization and the generated request were checked locally; no live VK community-token publication has been verified; the VK provider attempts to upload the featured image through VK photo APIs before publishing text, photo and link; errors are logged and a photo upload failure prevents publication. A live community-token request to photos.getWallUploadServer returned VK error 27 on 2026-11-09, so the current implementation fails before publishing the post; a supported solution for photos with this token remains unresolved. Local PHP checks cover successful upload, photo attachment, retry and VK error 27. Plugin version remains 0.4.10 while WordPress.org review is pending.

Facebook settings now include an OAuth connection using the administrator’s Meta application, a user-bound temporary state, long-lived user-token exchange, Page token lookup and token lifetime verification. Failures leave the existing Page token unchanged. The connection flow, rejection of short-lived tokens, invalid state, error codes and preservation of the previous token passed local checks with mocked Meta responses; PHP lint and 85 isolated assertions passed. No live Meta authorization has been performed. Plugin version remains unchanged.

Known admin UI issue: a narrow empty red strip appears below the Settings heading on the live site; its source has not yet been identified.
