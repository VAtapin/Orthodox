# Статус проекта «Приход»

## Текущее состояние

Самостоятельная тема `georg-kloster-prihod` 0.4.0 подготовлена в одноимённой
папке. Пакет `build/georg-kloster-prihod-0.4.0.zip` собирается командой
`python scripts/package.py --only theme` и предназначен для отдельной подачи
в WordPress.org. Тема работает без плагинов, использует стандартные страницы,
записи и навигацию WordPress и сохраняет пять оформлений: классическое,
гостеприимное, журнальное, традиционное и синее. Настройки находятся во
«Внешний вид → Оформление прихода». В панели остались общие параметры дизайна,
логотип, иконка и главное фото. Фотографии разделов и карточек, галерея и карта
удалены из настроек темы; изображения берутся из миниатюр и содержимого страниц.
Содержимое главной страницы, включая блоки плагинов, выводится открыто.
Публикация в каталоге не выполнялась.

Новый самостоятельный Core 0.1.0 находится в `georg-kloster-prihod-core/`.
Он хранит профиль, места служения и духовенство, даёт четыре блока и четыре
шорткода. Тема читает новый профиль при его наличии и продолжает работать
без него. Пакет `build/georg-kloster-prihod-core-0.1.0.zip` собирается через
`python scripts/package.py --only parish-core`. Старый `prihod/` пока сохранён
как исходник функций, которые предстоит перенести в Social и Schedule; новый
Core его не загружает. Старые отдельные коннекторы Telegram, WhatsApp и
Facebook пока не объединены. Порядок работы записан в
`docs/WORDPRESS_ORG_RELEASE_PLAN.md`.

На тестовом сайте `prihod.georg-kloster.ru` остаются ранее установленные
Core rc.20 и тема 0.3.28. Новая тема туда не устанавливалась. Обновление
общего Plesk-сервера выполняется только по отдельному прямому разрешению владельца.

## Принятые решения

Тема отвечает за оформление и не регистрирует собственные блоки, не создаёт
демо-страницы, не отправляет обращения и не меняет формы плагинов. Весь контент
и фотографии берутся с сайта владельца. Пять прежних JPG-превью сохранены в
исходниках для сравнения дизайна, но исключены из публичного ZIP из-за
неподтверждённых прав на фотографии. Скриншот каталога сделан с действительной
темы и нейтральных данных. Карта и формы принадлежат содержимому страниц и
соответствующим плагинам.

## Проверки

Проверены точный ZIP на WordPress 6.5/PHP 8.0 и WordPress 7.1/PHP 8.4 без Core,
а также совместимость с текущим Core на WordPress 7.1/PHP 8.4. Официальный
Theme Check прошёл без обязательных ошибок; оставшиеся рекомендации касаются
необязательных возможностей. После очистки настроек точный ZIP повторно прошёл
на WordPress 6.5/PHP 8.0 без плагинов и на WordPress 7.1/PHP 8.4 с текущим Core,
включая вывод блока Core через шаблон темы. Прошли 62 изолированных unit-проверки,
PHP lint, JS syntax и проверка 2271 переведённых сообщений. Пять оформлений
просмотрены в браузере на 1280 и 390 px без горизонтального переполнения.
`WP_DEBUG=true` использовался при локальном визуальном просмотре.
Для нового Core прошли PHP lint, JS syntax и проверка точного ZIP в чистом
WordPress Playground 6.5/PHP 8.0: активация, регистрация каталога и блоков,
сохранение профиля и вывод данных. Проверка не включала браузерную оценку
интерфейса или Plugin Check.

## Известные вопросы и следующие шаги

Старые интеграционные сценарии проверяют функции прежней блоковой темы
(`prihod-theme`, демо-импорт) и не относятся к чистой теме. Их нужно заменить
при разделении плагинов. Текущий CI проверяет точный ZIP темы, её совместимость
с Core и вывод блоков плагина, синтаксис, переводы и unit.
Следующие этапы: перенести обращения и каналы в Social, расписание и календарь
в Schedule, заменить старые интеграционные сценарии и проверить все четыре
пакета вместе. У нового Core пока нет мастера создания страниц; он не входит
в релиз 0.1.0. Подача в WordPress.org и обновление тестового сайта — отдельные
действия.
