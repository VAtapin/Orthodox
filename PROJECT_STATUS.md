# Project status: Georg-Kloster Prihod

## Current state

The repository contains the Georg-Kloster Prihod theme (1.0.0), Parish Core (0.2.12), and Connect Hub (0.4.10 candidate). The theme has five visual styles, native Customizer controls, standard WordPress widget and primary/footer menu locations, English gettext source strings, and Russian, German, Polish, and Ukrainian catalogs. Footer links are managed by assigning a standard menu to the Footer menu location. Author: Atapin Vladimir (`atapin`); site: https://georg-kloster.ru/; email: atapin@gmail.com.

The footer no longer generates a fixed list of site links. It renders the standard WordPress menu assigned to the Footer menu location; per-language menus can be assigned through the normal WordPress/WPML menu workflow. The theme package has not been installed on production.

The merged Parish Schedule reads vestment recommendations from Bible Desktop `day.vestment.color`; API `violet` maps to the existing `purple` palette key. Existing manual service colors and date overrides remain available. Vestment stripes use a silver frosted pattern; mobile upcoming-service cards and weekly/list event content have extra spacing after the stripe. Parish Core 0.2.12 keeps compact titles within their sidebar cards, shows all provider commemorations in full schedule service cards alongside typikon marks, and clears the overview heading from its calendar badge. Production has not been updated.

The theme has compact optional-plugin cards for Parish, Connect Hub, Calendar Workshop, Orthodox Donations, and Slavonic Translator. Language switching is delegated to WPML or Polylang. The shared homepage map uses a full-width iframe.

The active theme on the test site `new.georg-kloster.ru` was updated from the current Git package (version 1.0.0). News and category archives use responsive card grids. The homepage service strip has a place logo, date calendar, and time clock with separate columns for date, time, and service title; the time column is widened and its stylesheet uses a file modification cache key so updates reach visitors. Narrow screens stack the strip without clipping. The classic hero motto stays in the text column. The live page retained its existing theme settings.

The monastery icon category archive has a dedicated class and 16:9 featured-image cards. In Posts → Categories, each category can align card images to the center, top or bottom; center remains the default. Post editing includes an optional featured-image text-wrapping setting; wrapping is disabled by default and becomes a stacked image on narrow screens. Theme controls are translated into Russian, German, Polish, and Ukrainian. Changes are committed in the repository but have not been deployed to a site.

The native `/news/` Posts page and “News” category archive share the catalog’s category chips and search controls. Filter terms are limited to categories used by published posts, and selected search/category filters are applied to the correct main query. Translated page/category URLs are resolved through WPML or Polylang.

The newsletter widget area is present on the homepage and news/archive views. It uses MailPoet form 2 (“Новости монастыря”), linked to “Рассылка новостей”; the theme now constrains the form to a 600px maximum width and uses tighter spacing and shorter controls. The old stock demo form remains in MailPoet but is no longer displayed publicly. The confirmation email uses Russian text and the theme palette, and the confirmation page layout is compact with its sidebar hidden. Double opt-in and MailPoet’s built-in CAPTCHA are enabled. MailPoet sending is still inactive (“Other” method awaits activation); WP Mail SMTP has an SMTP transport configured, but delivery has not been tested. No campaign or test email has been sent.

Connect Hub 0.4.10 candidate keeps form notifications separate from public Telegram broadcasts. Forms send private inquiries only to their configured Chat IDs; publications go individually to each active bot subscriber who pressed `/start`. Bot language choices follow active WPML languages. Daily and weekly calendar messages use Telegram HTML and include every available commemoration and service, vestment-color markers and complete content split across Telegram-sized messages. Schedule messages list each service place once and link its address to Google Maps. News posts use the subscriber's translated title and a short HTML excerpt, the post's featured image, and a localized button that opens the translated article without printing its URL. News-command replies use the same compact format. Each Telegram command or reply can include localized inline buttons that open another configured command/reply or an HTTP(S) link. Incoming commands, form notifications, email replies, Telegram publications and subscriber broadcasts run in the triggering request without automatic retries. Calendar digests and scheduled publication rules retain their configured timing and then send directly. Forms and bot commands use separate WordPress-style list and edit screens. Bot replies use the WordPress visual editor with Telegram-supported formatting and up to ten photos or MP4 videos per language. Built-in and custom commands can return text, schedules, pages or news. Failed deliveries remain visible for manual retry. Standard interface text has RU/DE PO/MO catalogs. Production has not been updated.

## Connect Hub delivery

Connect Hub 0.4.10 sends Telegram updates synchronously to each subscriber's private chat, records individual outcomes, and permits manual retries after failure. Incoming bot commands, form notifications, replies by Telegram/email, webhook registration, and publications do not use delayed workers or automatic retries. WP-Cron remains only for calendar timing (daily digest and scheduled publication rules) and record retention. Non-Telegram social-channel processing is unchanged. Old queued items and stale scheduled hook records have not been migrated or deleted; legacy worker hooks are no longer registered. Installable package: `build/georg-kloster-connect-hub-0.4.10.zip`. The release candidate has not been installed on production or submitted to WordPress.org.
