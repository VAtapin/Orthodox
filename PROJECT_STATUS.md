# Статус «Прихода»

Готовы этапы 1–4, версия 0.4.0: Core, полное расписание, закрытые обращения,
безопасный мастер с анализом сайта, интервью, вводом мест/духовенства/первой службы,
планом, подтверждением, черновиками, отдельной публикацией и назначением главной/меню.
Повторный запуск сохраняет IDs, существующий контент и ручные изменения.
Есть patterns публикаций, диагностика, закрытый REST prihod/v1/status, управление
правами сотрудников и отдельное подтверждаемое фоновое удаление данных.

Решения: данные принадлежат плагину; optional тема/расширения самостоятельны.
Ответы мастера хранятся отдельно до подтверждения; устаревший snapshot не применяется.
Публикация не переписывает содержимое; изменённые вручную черновики проверяются в редакторе.
Существующие пользовательские страницы не удаляются при очистке. Созданные мастером
страницы удаляются только при отдельном выборе. Все массовые операции очистки — через cron.
Владелец устанавливает пакеты самостоятельно; его WordPress/production не изменялись.

Проверки: PHP 8.4 syntax, 56 unit assertions; WordPress 6.5.13 / PHP 8.4.25 / SQLite —
53 integration assertions, прошли. Проверены устаревшие планы, идемпотентность,
ручные правки, черновики, публикация, права, privacy, locks и явная фоновая очистка.
Diff/check/stat просмотрены перед commit. Живая почта, MySQL/Plesk, браузерная QA не проверены.

Далее: этап 5 необязательная тема, этап 6 реальные адаптеры календаря/Записок и сервисов.
Вложения и кабинет посетителя — дальнейшее развитие. При полном page cache нужно исключение
для одноразовой формы. WP-Cron необходим для email, retention и явно запущенной очистки.
Существующая навигация мастера при повторном запуске сохраняется, редактируется штатным редактором.
