# Независимые подключения «Прихода»

Три ZIP: prihod-telegram, prihod-whatsapp, prihod-social. Каждый работает с обычными
WordPress Posts без Core; при наличии «Прихода» регистрируется в общем обзоре.
Telegram имеет одно подключение для публикаций и уведомлений, не отдельные tokens
на каждую функцию. «Публикации» обслуживают Facebook Pages; Telegram использует
свой общий адаптер. WhatsApp — официальные шаблонные сообщения Cloud API.

Сборка из корня репозитория: `python scripts/package.py` (только стандартная библиотека).
Общий исходник копируется в каждый независимый ZIP. Устанавливать исходную папку
extensions прямо в WordPress не следует: устанавливаемым артефактом является ZIP.

По умолчанию отправки выключены. При активном Core настройки находятся внутри
«Приход → Наши плагины» и раздела «Приход → Настройки». Без Core подключение
имеет собственное меню плагина; общие «Настройки» WordPress не используются.
Токен вводится только в установленном WordPress, не в чат и не в Git; сохранённое
значение не отображается. Tokens хранятся в options без autoload: защищайте БД и backups.
Разрешения получателя и внешних аккаунтов настраиваются владельцем у провайдера.

Для Telegram: bot token и chat ID/@канал, бот с правом публикации.
Для Facebook: Page access token с правом публикации, Page ID и версия Graph API
из приложения. Личные аккаунты и группы этим адаптером не обслуживаются.
Для WhatsApp: business token, Phone number ID, версия Graph API, согласившийся
получатель, утверждённый шаблон с одним текстовым body-параметром и его язык.
Автоматизация личных аккаунтов и неподтверждённые шаблоны не используются.

В редакторе каждой записи явно выбрать канал. Скрытой автоматической рассылки нет.
Для уведомлений Core отдельно включить соответствующие флаги. О новых обращениях
передаётся только общий текст и ссылка в закрытый кабинет, без имени/email/вопроса.

Запросы выполняются фоновым WP-Cron с ограниченными повторными попытками.
Успех означает принятие запроса API, не подтверждение доставки человеку.
Живые API без аккаунтов и tokens не проверялись. Интеграционные тесты перехватывают
HTTP транспорт и проверяют реальные payload, очередь, отказ сервиса и повторную отправку.

Внешние сервисы, данные и условия:
- Telegram: текст публикации/общего уведомления, URL, chat ID; https://core.telegram.org/bots/api
- WhatsApp/Meta: шаблон, текстовый параметр, URL, номер получателя, Phone ID; https://developers.facebook.com/docs/whatsapp/cloud-api/
- Facebook/Meta: текст/ссылка опубликованной записи, Page ID; https://developers.facebook.com/docs/pages-api/posts/

При обычном удалении настройки и история задач сохраняются; сторонние публикации
не удаляются автоматически. Пакеты не выполняют установку друг друга или Core.
