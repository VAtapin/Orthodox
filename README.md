# Приход

Самостоятельный WordPress-плагин для православных храмов, приходов и монастырей.
Полный объём продукта зафиксирован в [ТЗ](docs/SPECIFICATION.md) и
[направлении проекта](docs/PROJECT_DIRECTION.md). Реализация выполняется по этапам
без сокращения конечных требований.

## Текущее состояние: 1.0.0-rc.7

Реализованы профиль прихода, места служения, духовенство, capabilities,
административное меню и PHP-контракт расширений. Один священнослужитель может быть
связан с несколькими местами служения. Каждое место может иметь собственный
именованный часовой пояс; пустое значение означает наследование часового пояса прихода.

Расписание поддерживает регулярные, разовые и праздничные службы, отмены,
переносы, изменение времени/места, неделю/месяц, фильтр, печать и ближайшую службу.
Доступны динамические блоки и шорткоды профиля, контактов, духовенства и расписания.
Обращения: форма без регистрации, закрытый кабинет, статусы, ответственные,
заметки, история, email-очередь, retention и WordPress privacy export/erase.
Мастер анализирует сайт и сохраняет интервью отдельно, показывает план,
создаёт черновики после подтверждения, публикует отдельно и повторяется без дублей.
Есть диагностика, права сотрудников и явно подтверждаемая фоновая очистка данных.
Необязательная тема `prihod-theme/` содержит шаблоны, patterns и варианты оформления,
работает с обычными страницами WordPress без плагина. Добавлены адаптеры существующих календаря и «Записок» и независимые подключения Telegram, WhatsApp и Facebook. Контракты и ограничения проверки описаны в [интеграциях](docs/INTEGRATIONS.md).

## Установка

Исходный каталог плагина — `prihod/`. Скопировать его целиком в
`wp-content/plugins/prihod/` существующего WordPress и активировать «Приход».
В админке появится меню «Приход». Заполнение доступно вручную и через мастер настройки.

Заявленный минимум: WordPress 6.5 и PHP 8.0. Production-окружение владельца:
Plesk и PHP 8.4. Отдельный Node build и Composer dependencies для плагина не нужны.
Проверка заявленного минимума должна дополняться интеграционными проверками WordPress.

Для сборки пяти независимых ZIP из корня репозитория (Python 3, без зависимостей):

```powershell
python scripts/package.py
```

Активация не меняет тему, меню, главную страницу или язык/часовой пояс WordPress.
Обычное удаление и деактивация сохраняют данные и выданные права. Инструмент
полного удаления данных доступен отдельным подтверждаемым действием с фоновой обработкой.
Сетевая активация: права инициализируются отдельно на каждом сайте при первой
загрузке активного плагина; данные хранятся в таблицах соответствующего сайта.

## Тема и интерфейс

Тема 0.3.17 содержит пять схем и пять семейств внутренних страниц по предоставленным
макетам. Core и тема имеют русский, немецкий, польский и украинский интерфейс.
Мастер показывает шесть крупных этапов, сохраняя подробное интервью и отдельные
подтверждения. Фотографии выбираются из медиатеки; языковой переключатель ведёт
только на существующие версии. См. [тему](prihod-theme/README.md) и
[визуальные ориентиры](docs/design-reference/README.md).

## Права

При первичной установке права получает администратор текущего сайта.
Проверки доступа используют capabilities, а не название роли. При обычной загрузке
плагин не восстанавливает отозванные права. При повторной активации начальные
права администратора выдаются заново.

| Capability | Назначение |
| --- | --- |
| `manage_prihod` | Профиль, места служения, духовенство |
| `manage_prihod_settings` | Настройки и подключения |
| `manage_prihod_schedule` | Управление расписанием |
| `view_prihod_requests` | Просмотр обращений |
| `reply_prihod_requests` | Ответы |
| `assign_prihod_requests` | Назначение ответственного |
| `delete_prihod_requests` | Удаление обращений |

Права сотрудников назначаются в «Приход → Права сотрудников» пользователем с
`promote_users` и `manage_prihod_settings`. Роли WordPress не переписываются.

## Проверки

```powershell
php tests/lint.php
php tests/run.php
```

Альтернатива при настроенном Composer: `composer check`. Установка зависимостей
не требуется. Unit-тесты используют изолированные подстановки функций WordPress;
они проверяют валидацию, сохранение данных, ограничения доступа и ошибки расширений.
Это не замена запуску плагина в WordPress. Интеграционный сценарий и его команда
описаны в `tests/README.md`.

## Архитектура и следующие этапы

См. [архитектуру](docs/ARCHITECTURE.md) и [статус](PROJECT_STATUS.md).
Реализация этапов 1–6 подготовлена как release candidate. Далее — проверка на тестовом сайте владельца, визуальная QA и проверка доставки с его аккаунтами.

Шорткоды: `[prihod_profile]`, `[prihod_contacts]`, `[prihod_clergy]`,
`[prihod_schedule view="week"]`, `[prihod_schedule view="month" location="123"]`,
`[prihod_next_service]`, `[prihod_next_services limit="5"]`.
Ближайшие службы ищутся на 366 дней вперёд. Весенний DST gap пропускается,
осенний fold использует первое вхождение. Исключения относятся к исходной дате
службы. Модуль отключается в настройках без удаления данных.

Форма: `[prihod_requests]` или блок «Вопрос священнику». Требует отдельной страницы
политики конфиденциальности сайта. При полном page cache исключить страницу формы
из кэша: одноразовый токен действует час. Фоновая email-доставка и retention используют
WP-Cron; успешный wp_mail означает принятие письма транспортом, не получение адресатом.
Закрытые обращения удаляются через 365 дней после изменения (настраивается 30–3650).

## Проверка установленного WordPress

По прямому разрешению владельца установлен WordPress на prihod.georg-kloster.ru.
Это отдельный сайт на общем боевом Plesk-сервере. Все дальнейшие действия ограничены
WordPress: окружение сервера и другие сайты не изменять; блокировки не добавлять.
Фактическое окружение этого сайта — PHP 8.5.11, MariaDB 10.6.23.
Состояние и команды — docs/TEST_SERVER.md. Корень Git checkout не устанавливается
в webroot. Сборки Core, темы и подключений находятся в build/.

«Приход» открывает дашборд. Меню разделено на информацию, обращения, наши плагины,
настройки и мастер. В консоли WordPress есть четыре блока с реальными сведениями,
службами, статусами обращений и подключениями. Данные обращений защищены capabilities.

Тема 0.3.17 имеет собственную панель управления внутри «Приход → Настройки»:
семь разделов, пять оформлений, макет/шрифты, фото/логотип, шапка/подвал, формы,
языки и импорт редактируемых демо-страниц. Импорт использует существующий мастер
Core, сохраняет материалы и поддерживает самостоятельную тему. По умолчанию
создаются черновики; публикация, главная и меню выбираются отдельно.

Лицензия: GPL-2.0-or-later, https://www.gnu.org/licenses/old-licenses/gpl-2.0.html.

По запросу владельца опубликованы и наполнены все 13 демо-страниц монастыря.
Сведения, источники, повторный импорт и снимки — [docs/MONASTERY_DEMO.md](docs/MONASTERY_DEMO.md).
Внутренние экраны имеют общую верхнюю навигацию к «Обзору прихода»; редактор
службы группирует основные поля, дополнительные сведения раскрываются отдельно.

Публичное расписание показывает ближайшую реальную службу и изменения периода
перед переключателями вида. Исходящие переносы не исчезают из обзора; мини-месяц
различает сегодня, выбранную неделю, службы и исключения. Чтение не меняет данные.


Форма «Вопрос священнику» использует тематический выбор и вариант «Другая тема».
Своё название проходит прежнюю проверку/обработчик и хранится как обычная тема
закрытого обращения; старые свободные темы совместимы. Обязательные поля и подсказки
локализованы. Фото заголовка выбирается в разделе фотографий темы; текст страницы
не перезаписывается. JavaScript только показывает условное поле, сервер проверяет его
самостоятельно, форма остаётся доступной без JavaScript.


Каталоги новостей/проповедей используют существующие Query Loop и опубликованные
WordPress Posts. Поиск, реальные рубрики, сброс и штатная пагинация сохраняют
выбранные параметры и предпросмотр. Карточки: фото, дата, название, анонс, чтение.
Каталог занимает полную ширину. Текст страницы не сохраняется при оформлении;
произвольные сложные карточки владельца и Query-блоки вне её контента сохраняются.

На неизменённой демо-странице духовенства точный повтор биографии объединяется
с живым каталогом в компактную карточку. Исходный текст, ручные правки,
пользовательский шаблон и несколько священнослужителей сохраняют свой вывод.


«Паломнику» в неизменённом демо оформляется по эталону 11: широкая фото-полоса,
быстрые переходы, фотографии, посещение/согласование группы и дорога с картой.
Фото выбираются в панели темы. Штатная иерархия WordPress выбирает композицию,
не сохраняя шаблон/контент; ручная редактура и собственные шаблоны имеют приоритет.
Пребывание не обещается: предлагается заранее согласовать его через настоящий контакт.

Страница контактов использует прежний нативный блок и его данные: контакты перед
дорогой, нажимаемый телефон, небольшое фото и существующая карта. Автоматический
вывод применяется только к неизменённому демо с обычным шаблоном; ручные правки и
Site Editor имеют приоритет. Версия темы 0.3.16 проверена локально и установлена по разрешению владельца;
62 проверки живого WordPress и пять оформлений desktop/mobile прошли.

Локальная тема 0.3.17 дополняет пять главных управляемыми девизами classic и отдельной
цитатой blue; текст/source в «Шапка и подвал». Общая цитата также появляется в шапке
editorial. Пустое значение убирает блок. Фото владельца имеют приоритет над символами
tradition; портреты не режутся по лицу. На сервере пока 0.3.16.
