# Подключение каналов Connect Hub

Откройте **Connect Hub → Settings** и выберите вкладку нужной сети. Вкладки Facebook, Instagram, VK и OK публикуют выбранные записи/сообщения WordPress в публичной ленте. Входящие обращения из форм идут по email и, при включении, в Telegram. Telegram использует один токен бота, но Chat ID и ответственного сотрудника можно задать отдельно в каждой форме.

Токены и секретные ключи — пароли интеграций. Вставляйте их только в настройки WordPress по HTTPS; не присылайте их в чат, не помещайте в публикации и не храните в общедоступных файлах.

## Telegram

### Создать бота и подключить общий канал

1. Откройте [@BotFather](https://t.me/BotFather), нажмите **Start**, отправьте `/newbot`, задайте отображаемое имя, затем уникальный username, который заканчивается на `bot`.
2. Скопируйте выданный BotFather токен и вставьте его в **Connect Hub → Settings → Telegram → Token**. Токен включает числовой ID, двоеточие и секретную часть. Не вводите username бота вместо токена.
3. Откройте созданного бота по ссылке от BotFather и нажмите **Start**. Чтобы узнать свой личный числовой ID, можно открыть [@userinfobot](https://t.me/userinfobot); это сторонний справочный бот Telegram.
4. В поле **Chat ID / @channel** укажите личный числовой ID администратора. Это общий адрес по умолчанию для форм, где индивидуальный ID не задан. Для личных ответов здесь нужен именно личный ID, а не имя бота или `@username`.
5. Отметьте **Allow sending to the external service** и **Notify about new messages**, затем сохраните настройки.

### Назначить свой чат каждому отделу

1. Откройте **Connect Hub → Forms**, нажмите название нужной формы/отдела.
2. Ответственный сотрудник должен открыть именно созданного вами бота и нажать **Start**. Бот не может первым открыть личный чат.
3. Сотрудник узнаёт свой личный числовой ID через [@userinfobot](https://t.me/userinfobot). Введите этот ID в поле **Private Telegram Chat ID** формы. Для каждого отдела можно указать отдельный ID. Если поле оставить пустым, используется общий ID из настроек Telegram.
4. В списке **Save Telegram replies as this staff member** выберите WordPress-аккаунт ответственного. У него должны быть права просматривать обращения и отвечать на них. Пустое значение использует общего сотрудника из Telegram-настроек.
5. Сохраните форму. Повторите это для остальных отделов и проверьте каждый отдельной тестовой отправкой.

### Ответы из Telegram

Чтобы сотрудник видел полный текст и мог ответить посетителю непосредственно в Telegram, в **Settings → Telegram** включите **Send complete messages and receive replies in a private chat**, сохраните настройки, затем нажмите **Connect / check incoming replies**. Сотрудник отвечает именно командой Telegram **Reply** на сообщение бота с соответствующим обращением. Ответ сохранится в истории обращения от имени выбранного WordPress-сотрудника и будет отправлен автору обращения по email. Для разных отделов маршруты и ответственные разные, webhook и токен бота общие.

Индивидуальные назначения поддерживают личные числовые Chat ID. Группы и каналы не подходят для приватного цикла ответа. До включения полного текста убедитесь, что в чате находится только ответственный сотрудник: Telegram получит имя, email, тему и текст обращения.

Официальные ссылки: [BotFather](https://t.me/BotFather) · [Telegram Bot API](https://core.telegram.org/bots/api) · [как работают боты и личные чаты](https://core.telegram.org/bots/features#botfather).

## Facebook

Этот раздел публикует выбранный текст и ссылку в Facebook Page; он не распределяет обращения из форм.

1. Откройте [Meta for Developers — Apps](https://developers.facebook.com/apps/) и создайте/выберите приложение. У аккаунта должны быть права на целевую Facebook Page.
2. В приложении добавьте нужный сценарий Pages API. Откройте [Graph API Explorer](https://developers.facebook.com/tools/explorer/), выберите своё приложение и запросите **Page Access Token** нужной страницы. Для публикации используются разрешения `pages_manage_posts` и `pages_read_engagement`. В зависимости от режима приложения, аккаунта и использования вне его ролей Meta может потребовать App Review/Advanced Access.
3. Вставьте Page Access Token в поле **Token**. В поле **Facebook Page ID** укажите числовой ID страницы. Не вводите пароль Facebook, App Secret или ID личного профиля.
4. Выберите в Graph API Explorer доступную версию рядом с API-запросом и скопируйте её в **API version** точно, вместе с `v`, например в форме `vNN.N`. Это только версия URL Graph API, не ключ и не версия Connect Hub. Meta периодически выводит версии из поддержки, поэтому ориентируйтесь на доступный список версий и [политику версионирования](https://developers.facebook.com/docs/graph-api/overview/versioning/).
5. Сохраните настройки, включите отправку и проверьте канал на тестовой опубликованной записи.

Ссылки: [создание приложения](https://developers.facebook.com/apps/) · [Pages API: начало работы](https://developers.facebook.com/docs/pages-api/getting-started/) · [публикация постов](https://developers.facebook.com/docs/pages-api/posts/) · [Graph API Explorer](https://developers.facebook.com/tools/explorer/).

## Instagram

Этот раздел публикует изображение и подпись в профессиональном Instagram-аккаунте; обычные личные аккаунты не поддерживаются. Он не распределяет обращения из форм.

1. Переключите Instagram на профессиональный аккаунт **Business** или **Creator** и свяжите его с Facebook Page.
2. В [Meta for Developers](https://developers.facebook.com/apps/) создайте/выберите приложение и настройте Instagram API with Facebook Login. В [Graph API Explorer](https://developers.facebook.com/tools/explorer/) получите user access token с `instagram_basic` и `instagram_content_publish`. Для получения списка связанных Pages может понадобиться `pages_show_list`. Если приложение используется за пределами его тестовых ролей, Meta может потребовать App Review/Advanced Access.
3. Вставьте токен в **Token**. В **Instagram account ID** введите ID профессионального Instagram-аккаунта, связанного с Page. Это не username и не Page ID; связанный объект обычно доступен как `instagram_business_account.id` у Page в Graph API Explorer.
4. Выберите версию Graph API из списка в Explorer и скопируйте в **API version** точно с префиксом `v` (формат `vNN.N`). Это не секрет и не версия плагина.
5. Для каждой публикации выберите JPEG-изображение записи. Оно должно иметь публичный HTTPS URL, доступный серверам Meta. Сохраните настройки и проверьте тестовой публикацией.

Ссылки: [Instagram Platform](https://developers.facebook.com/docs/instagram-platform/) · [публикация контента](https://developers.facebook.com/docs/instagram-platform/content-publishing/) · [Graph API Explorer](https://developers.facebook.com/tools/explorer/).

## ВКонтакте (VK)

Этот раздел публикует текст и ссылку в выбранную стену VK; он не распределяет обращения из форм.

1. Откройте [VK для разработчиков](https://dev.vk.com/ru), войдите в аккаунт и создайте приложение согласно актуальным указаниям портала.
2. Создайте access token с разрешением на публикацию на стене (`wall`). Вставьте токен в **Token**. Не вводите пароль VK.
3. В **VK owner ID** укажите цель: отрицательный числовой ID сообщества (например, `-123456`) для публикации в группе или положительный ID профиля для личной стены. У токена должны быть права на эту стену.
4. **API version** — версия метода VK API, используемая запросом. Откройте документацию метода `wall.post` и скопируйте поддерживаемую версию в формате цифры-точка-цифры, например `5.199`. Префикс `v` не добавляйте. Версия не является токеном или ключом.
5. Сохраните настройки, включите канал и проверьте тестовой записью.

Ссылки: [VK Dev](https://dev.vk.com/ru) · [access tokens](https://dev.vk.com/ru/api/access-token/getting-started) · [wall.post](https://dev.vk.com/ru/method/wall.post).

## Одноклассники (OK)

Раздел предназначен для публикации текстового медиатопика в группу OK. Новые приложения через прежний интерфейс создания приложений OK сейчас не регистрируются; существующие приложения продолжают работать. Если у вас нет приложения, сначала проверьте актуальный путь создания в [официальной документации OK](https://apiok.ru/dev/app/create) и условия разработчика.

1. Для существующего приложения найдите ID приложения, публичный ключ и секретный ключ в его настройках или регистрационном письме. Не помещайте секрет в публичное поле.
2. В **Token** вставьте access token. В **OK group ID** укажите числовой ID целевой группы. Ни ID приложения, ни публичный ключ не являются Group ID.
3. Введите **Application public key** и **Application secret** в одноимённые поля. Приложению требуется доступ `GROUP_CONTENT`. После изменения разрешений получите новый access token.
4. Сохраните и проверьте тестовой публикацией. Для OK версия API в настройках Connect Hub не задаётся.

Ссылки: [официальное уведомление и сведения о приложениях OK](https://apiok.ru/dev/app/create) · [mediatopic.post](https://apiok.ru/dev/methods/rest/mediatopic/mediatopic.post) · [права приложений](https://apiok.ru/ext/oauth/permissions).

## Что вводить в API version

| Вкладка | Значение |
| --- | --- |
| Facebook | Версия Meta Graph API, включая `v`, например `vNN.N` |
| Instagram | Версия Meta Graph API, включая `v`, например `vNN.N` |
| VK | Версия VK API без `v`, например `5.199` |
| Telegram, OK | Поле версии не используется |

Значение версии не секретно. Оно обозначает контракт API, к которому плагин обращается. При выборе сверяйтесь с актуальной официальной документацией сети: поддерживаемые версии со временем меняются.
